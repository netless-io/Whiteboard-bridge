## 一、主要修复

### 1.1 房间 API 调用异常或一直等待

Harmony 上调用 `getRoomState()`、`getEntireScenes()` 等接口时，正常返回的数据可能被错误识别，出现类型错误。部分场景下，多窗口查询、关闭 App、翻页或插入文字也可能无法返回结果，或将失败误报为成功。

本版修正数据解析和错误返回，补齐缺少调用条件及异步失败时的回调；同时核对 Android、iOS 的成功返回格式和错误处理，保留原有接口使用方式。

### 1.2 关闭白板后再次进入可能失败

未主动离房就关闭白板页面，或离房尚未完成就销毁页面时，旧页面的房间记录可能未被清理，导致新页面再次进入相同房间、相同用户时失败或持续加载。

本版在白板实际销毁时释放对应记录。**正常销毁后，新页面可直接开始入房，不会额外等待旧页面的固定离房超时。** 新页面初始化和网络入房本身仍需要正常耗时。

保留原页面、直接再次调用 `joinRoom` 时，SDK 内部先退出原房间，再进入本次房间；多页面存活时，相同 App、房间和用户的接替也由 SDK 内部处理。旧页面稍后关闭，不会误清理新页面的房间记录。

网络或退出异常时，SDK 记录异常并继续本次入房，避免旧退出失败持续阻断业务；此类异常恢复期间，旧连接可能短暂延迟释放。

## 二、安装与升级

### 2.1 Android

保留现有 JitPack 仓库配置，更新依赖：

```groovy
implementation 'com.github.netless-io:whiteboard-android:2.16.137'
```

### 2.2 iOS：使用 Git tag 引用

与上一版保持一致，通过 CocoaPods 固定引用本次发布 tag：

```ruby
pod 'Whiteboard',
    :git => 'https://github.com/netless-io/Whiteboard-iOS.git',
    :tag => '2.16.150'
```

执行 `pod install`；已有工程按锁文件规则更新 Whiteboard。此方式仍由 CocoaPods 管理依赖，将 Whiteboard 源码固定为本次 Git tag。

### 2.3 HarmonyOS

OHPM 审核通过后更新依赖：

```bash
ohpm install @shengwang/whiteboard@0.2.14
```

审核期间可从 [GitHub Release](https://github.com/netless-io/whiteboard-harmony/releases/tag/0.2.14) 获取 HAR；OHPM 当前状态见上表。

## 四、升级建议

建议上述旧版本客户升级，优先覆盖使用 Harmony 房间 API、直接关闭白板页面、快速退出重进或多页面接替的业务。

已使用 `leaveRoom` / `disconnect` 的业务可保留原调用；通过页面卸载移除白板的业务，无需仅为本次修复补加显式离房或 WebView 销毁调用。仅隐藏页面、仍持有原白板实例时，SDK 会按存活实例处理，再次入房时内部完成旧房间接替。
